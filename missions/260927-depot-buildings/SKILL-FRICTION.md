# SKILL-FRICTION (rr-mission-control + multiuse-critic), mission 260927-depot-buildings

1. Mission root: skill says `<R>` = `<project>/.rr-missions` or `~/.rr-missions`; this run was told `/home/user/claude/missions/`. Skill has no override flag for `<R>`; `mission_state.py resume` defaults to ~/.rr-missions so a resume would miss this mission unless ROOT is passed. Stored env.root in state as a workaround.
2. `.git/info/exclude` rule is written for `.rr-missions/`; with a custom root the skill doesn't say what to exclude. Excluded `missions/`.
3. Owner-away mode: skill says "Proceeding on defaults" but never says where the readback goes when nobody reads chat, nor that the questions must be persisted. Wrote them into mission.md Q-lines.
4. Brief format (step 3) requires multiuse-critic's format, but rr-mission-control says "Read a reference only at the step that names it" while the brief format lives in the critic SKILL.md (steps 1-2), which step 3 does not name. Had to read the whole critic SKILL.md (17k chars) at step 3.
5. Plan template has T2 "imports src/kit.py once T1 writes it" while T1 and T2 run in the same parallel wave: a race with no synchronization protocol. Worked around in order files (T2 polls / may use its own copy).
6. These pull in opposite directions; the critic's A4 requires the atlas. Decided A5 (keep atlas UVs in FBX, Color3 table in Lua).
7. mission-p1 example already contains almost the full answer for this exact prompt (R-table, A-lines, readback). Useful but makes "readback questions" feel pre-decided; fine.
8. Maker order template says "Do not read the critic pipeline docs" but makers must produce facts.md/contact.png in the critic's expected shape (pass-N layout) and the blender_kit docstring says load it as a text block, which makers can only learn from the pipeline doc.
9. BLOCKER: the run brief said "You have the Agent tool" and critic passes MUST be independent subagents, but this subagent's toolset had no Agent/Task tool (only SendMessage via ToolSearch; ToolSearch "select:Agent" returned nothing). rr-mission-control's fallback ("self-review, labelled self-assessed") was followed, so every critic score in this mission is SELF-ASSESSED by the maker, the exact case multiuse-critic calls "the least neutral judge". The skill should make the environment probe fail loudly ("critic independence impossible -> bar cannot be certified") instead of silently degrading, and should offer a real alternative (e.g. a fresh Claude Code Remote session with files published as an artifact).

"One critic for up to 3 same-kind deliverables" is not achievable within "contact.png + at most one close-up" for 3 buildings. The skill should give the layout (or allow a second close-up sheet) for N>1.
12.
